# FFmpeg GUI

一个基于 ffmpeg / ffprobe 的 Windows 桌面批量处理工具。把一整个文件夹丢进去，  
选一个模板，剩下的交给它：转码、缩放、改容器、抽音轨、转 GIF，以及你临时加的  
任意 ffmpeg 参数。

## 它能做什么

- **批量处理** — 拖入文件或整个目录，递归扫描子目录，一次跑完整批。
- **参数模板** — 把一套 ffmpeg 参数存成模板，随时切换；可复制、可另存为新模板。
- **分辨率批量转换** — 4K 长边转 2K 这类需求，横屏竖屏自动识别。锁定长边或短边时  
  另一边交给 ffmpeg 按比例计算（命令里是 `-1` / `-2`），程序不做任何取整猜测。
- **命令行预览** — 每个模板、每个任务都能看到将要执行的完整命令，逐行展开。
- **实时监控** — 速度、码率、进度、ffmpeg 原始日志，任务卡里一目了然。
- **后台运行** — 最小化到系统托盘，处理期间可以锁屏继续干活。
- **处理记录** — 记录处理前后的格式、分辨率、体积与压缩比，可导出 CSV。

## 快速开始

### 1. 准备 ffmpeg

程序需要 `ffmpeg` 和 `ffprobe` 两个可执行文件。

- **已经装过**：直接启动即可，程序会从系统 `PATH` 里自动查找。
- **没有装**：从 [ffmpeg.org/download](https://ffmpeg.org/download.html) 下载  
  Windows 版本，解压后打开  
  「设置 → FFmpeg 程序」，把 `ffmpeg.exe` 和 `ffprobe.exe` 的路径填进去。

程序不会附带 ffmpeg，也没有隐藏的下载逻辑 —— 用哪个版本完全由你决定。

> 想要 NVENC / QSV / AMF 硬件编码，需要用带这些编码器的 ffmpeg 构建。  
> 模板编辑器里的「可用的视频编码器」会实时检测当前 ffmpeg 到底支持哪些，  
> 不支持的会灰掉，避免选了才发现。

### 2. 添加文件

把文件或文件夹拖进窗口，或者点「添加文件」「添加文件夹」。目录会递归扫描，  
常见的视频与音频格式都会入队。

过滤的那一套规则在侧栏的「过滤」页里设（不在工具栏上做成弹窗了）。一套**方案**里有  
**两组各自独立**的规则：一组按**目录名**挑文件夹，一组按**文件名**挑文件 —— 它们回答  
的是两个问题，"这个文件夹里往下收哪几个目录"和"收进来的文件里再要哪几个"；合成一份  
条件会让两边都写不准，而且从界面上看不出是哪一边错了。

两组条件的写法一样：前缀、后缀、包含、通配符四种，值里带 `*` 或 `?` 时自动按通配符  
比；可以加多条条件，并选择「满足全部」还是满足任意一条（例如先挑 `ffmpeg__*`、再挑名字  
里带 `h265` 的）。条件都不填就是整个目录 / 所有文件。比较的是名字，不分大小写。  
「文件规则」比的是**文件名**，和模板里那套按体积、时长、扩展名排除文件的「匹配条件」  
是两回事，互不影响。

**你添加的那个目录自己也算一个候选。** 它是你亲手挑的，名字命中就整棵都要（关掉  
「含子目录」就是要它这一层）—— 所以条件写「包含 1」、挑的文件夹叫 `123` 时，里面的  
文件会照常收进来，因为这个文件夹本身就是符合条件的。

同一个条件有两个方向。默认是**收**：命中就收进来。打开「排除」之后反过来用：命中的  
目录不要，连它下面整棵子树一起不要，其余照收 —— 想排除 `cache`、`node_modules`  
这类目录时用这个方向，不必把想收的那几个一条条列出来。「排除」不把你添加的那个目录  
算进命中：那边的意思是"整个文件夹减去几个"，落点就是那个文件夹，命中的是它的子目录。  
文件那一组的「排除」是同一个意思：命中的文件不收。

**「含子目录」只在目录那一组里**（文件名没有"往下收多深"这回事），管的是往下收多深：  
开着（默认）会走完整棵子树，命中的目录连它下面的内容一起收；关掉只看你添加的那一层  
——它自己加上它的**直接子目录**，命中的目录也只收它自己直接放着的文件。这一颗不跟着  
「启用」走，过滤关掉时它照样算数。

**两组各有一个「启用」开关**：关掉哪一组那一组就整个不参与，条件还留着，下次打开就能  
接着用。两边都关着就是整个文件夹照收。

**一次设好、一套套存着用。** 一套方案可以新建、复制、另存为、删除；任务页工具栏上「过滤」  
那颗下拉列的就是它们，下拉第一项是**「不使用过滤」**。在那里选哪套就是**此刻在用**哪套，  
下次打开从它开始；而「不使用过滤」只对这一次运行有效——关掉程序再打开，回到上次选的那套  
（一个文件夹都不筛，全照收）。之后每次「添加文件夹」、拖入文件夹，以及「添加文件」，都按  
当前生效的那一套收，不再逐个问。选中「不使用过滤」时那颗下拉会变成虚线：说错了的代价是  
收进来一堆本该跳过的文件，得一眼看得出这批是没过滤的。

「过滤」页的左边是方案表：搜索框按**名字和说明**筛，右上角那颗 `+` 新建，**右键方案行**有  
「复制方案 / 删除方案」。**方案名称和说明在右侧「基本信息」里直接改**，不用弹窗。  
列表支持 Ctrl 和 Shift 多选（Ctrl+A 全选），勾几行就能一次删掉几套。

「过滤」页下半部分有个「试一个文件夹」，把目录路径填进去就能看到当前这套规则的结果：  
收的方向下列出会收进哪些目录、各带几个文件，文件规则又筛掉了几个；排除方向下列出会被  
跳过的目录、以及最后还剩多少个文件。路径可以直接手输，也可以点右边的「选择」从资源  
管理器里挑。点名的文件和拖进来的文件也一样过文件规则。

### 3. 选模板，点开始

在工具栏第二行「模板」那颗下拉里选模板，点「开始」。每个任务都会显示进度、速度与耗时，  
处理完的文件落在输出目录里。

**队列不会自己开跑。** 添加文件、拖入文件、切换模板都只是把任务排进去，必须点  
「开始」才会处理；「暂停」会**把正在转码的进程也一起冻住**——进度停在原地，点  
「继续」后从那里接着转，不会重新开始，也不丢已转的部分；「停止」把队列退回未开始  
的状态。「暂停」在还没点过「开始」时是灰的——队列没启动过，暂停它没有意义。  

暂停中的任务会显示「已暂停」，进度条不再走动——这不是卡死，是真的停住了。  
如果你在暂停时直接关掉程序，那个转了一半的文件不会留下任何标记：下次遇到同一个  
源文件会照常重新转一遍，覆盖掉它。

## 模板

模板决定「怎么转」。一个模板包含：编码器与码率控制、分辨率、音频、容器与流、  
滤镜、以及你自己加的额外参数。

程序内置了 11 个常用模板（无损转封装、H.264 1080p、H.265 高压缩、  
4K 长边转 2K、竖屏 1080×1920、定码率、抽音频、Web 优化、转 GIF 等），  
可以直接用，也可以复制一份改成自己的。**列表里的模板可以拖动调整顺序**，  
顺序会保存下来。搜索框按名字和说明筛，右上角那颗 `+` 新建模板，**右键模板行**  
有「复制模板 / 删除模板」。列表支持 Ctrl 和 Shift 多选（Ctrl+A 全选），勾几行就能  
一次删掉几套；列表最上面那一行是**「基本配置」**（全局默认值），它不能复制也不能删除，  
勾选时会被跳过。**模板名称和说明在右侧「基本信息」里直接改**，左下角只标「有未保存的修改」。

**哪些参数可以不填**：ffmpeg 本身有默认值的参数，留空即可 —— 程序不会把  
`-crf`、`-b:v`、`-preset`、`-max_muxing_queue_size` 之类硬塞进命令。  
留空就是「交给 ffmpeg 决定」。

**编码器留空**则完全不传 `-c:v`，连带的 CRF / 码率 / preset 也会一起跳过 ——  
因为编码器家族不同，质量参数的写法也不同（libx264/x265 用 `-crf`，  
NVENC / QSV / AMF 用 `-cq`），猜错比不写更糟。只有在你确实填过又被跳过时，  
预览才会给出提示。

**「不填」在界面上只有一种说法**：下拉框叫「默认（由 ffmpeg 决定）」，输入框的  
占位文字是「留空 = 默认」，数值填 0 表示「保持原样」或「不限」。

**输入框随选项联动**：选了「锁定长边」，短边、宽高、百分比这些与当前方式无关的  
框会灰掉；视频选「直接复制」时编码器整组不可用；「被排除文件的处理」选了「留在  
原处」时，整组目标目录都不可用。灰掉的不是被丢弃，只是这一项本来就不会进命令。

**新建模板的音频默认是「直接复制」**：多数任务只想重编码视频，音频原样带走既省  
时间也不会更差。

## 全局默认值与「跟随」

模板列表的第一项是**基本配置**（全局默认值）。它不是预设，不参与处理，只提供
默认值，也不能删除或另存为。

- 新建模板时以它为起点。
- 模板里每一段都有一个「与全局不同」开关：关掉就跟随全局，打开才单独编辑。  
  跟随时那一段只显示一行摘要，告诉你正在继承什么，而不是摆一屏用不上的输入框。
- 五段都受这个开关管：**处理性能 / 输出与命名 / 已处理过的文件 / 匹配条件 / 错误与警告**。

「与全局不同」是**唯一**表达「跟随」的方式。段内下拉框里没有「跟随全局设置」这一项，
段内字段留空也**不是**再跟一次全局——留空各有各的本来意思（目录=源文件所在目录，
名称=源文件名）。一个状态给两个控件、一个意思给两种说法，界面上就可能出现
「看着在跟随、命令里却是别的值」。

所以调整默认行为只需要改一处；要给某个模板破例，单独打开那一段即可。

## 输出与命名

**产物放哪**由一个「输出方式」加几个填写框决定，主输出、被筛掉的文件、
「已处理过的文件」、错误 / 警告文件都用这一组。

| 输出方式       | 落到哪                                                |
| ---------- | --------------------------------------------------- |
| 原目录       | 源文件所在目录                                              |
| 自定义目录     | 你填的目录。写什么就是什么，后面不会再接任何东西（`C:/video` 就是 `C://video`） |
| 同级目录     | 你**添加的那个目录旁边**新建一个 `前缀 + 它的名字 + 后缀` 目录         |
| 同级顶层目录   | **文件自己所在目录**旁边新建一个 `前缀 + 该目录名 + 后缀` 目录           |

两个「同级」的**区别只在基准**（也就是那个 `前缀…后缀` 拼的是谁的名字），前缀和后缀
两个框在两种方式下是同一套拼法：

- **同级目录**量的是**你添加的那个目录**。添加 `D://video`、配上 `123_` 和 `_out`，
  产物落在 `D://123_video_out` —— `video` 下面有几层子目录都汇到这一个目录，形状靠
  「保留目录结构」恢复。
- **同级顶层目录**量的是**文件具体在哪个目录**。同样添加 `D://video`，`video\1` 里的
  文件落到 `D://video\123_1_out`，`video\2` 里的落到 `D://video\123_2_out` —— 每个子
  目录旁边各出一个自己的。

两边都留空会补一个 `_out` —— 否则拼出来的就是那个目录自己，产物会和输入挤在同一个
文件夹里。（单个拖进来的文件没有"添加的目录"这层，这时它自己所在的目录就扮演那个角色。）

**留空只有一个意思：最朴素的默认。** 不管这一段是不是「与全局不同」都成立——跟随
全局只有段头那个开关一种说法，框里留空不会再偷偷跟一次。「自定义目录」留空 =
源文件所在目录。

**「保留目录结构」把源文件的子目录补在目标目录下面**：打开后整棵树的形状跟着出去，
关掉就全部贴平到同一个目录（这时重名只能靠 `_1`、`_2` 挡）。子目录是相对你**添加的
那个目录**算的。

```
添加的目录                D://video//mmd
  同级目录 + 后缀 _out + 保留目录结构：
    其中的            D://video//mmd//a.mp4        →  D://video//mmd_out//a.mp4
    子目录里的          D://video//mmd//sub//b.mp4  →  D://video//mmd_out//sub//b.mp4
    更深一层的          D://video//mmd//x//y//c.mp4  →  D://video//mmd_out//x//y//c.mp4
  同级顶层目录 + 后缀 _out：
    其中的            D://video//mmd//a.mp4        →  D://video//mmd_out//a.mp4
    子目录里的          D://video//mmd//sub//b.mp4  →  D://video//mmd//sub_out//b.mp4
    更深一层的          D://video//mmd//x//y//c.mp4  →  D://video//mmd//x//y_out//c.mp4
  自定义目录 D://Media + 保留目录结构：
    子目录里的          D://video//mmd//sub//b.mp4  →  D://Media//sub//b.mp4
```

「原目录」和「同级顶层目录」用不上这个开关：前者的结构本来就在那里，后者的基准就是
文件自己的目录、没有子目录可以往回接。这个开关在那两种方式下会灰掉。

**「路径测试」**在「输出与命名」段的最下面：填一个输入文件（也可以点「选择文件」），
它会按上面这套规则算出这个文件会被写到哪 —— 源文件目录、输出目录、输出文件三行。
它不读文件内容，所以一边改规则一边就能看到结果。面板里只有**一个**输入文件，没有
「添加目录」这一层，所以选「同级目录」时它只能拿文件自己所在的目录当基准，答案下面
会写明这一点。

**默认是「同级目录 + 后缀 `_out`」+ 保留目录结构**，也是推荐写法：结果落在**你添加的
那个目录**的同级位置，而不是那棵树里面。这意味着再次扫描同一个目录时，不会把上次生成
的产物再吃一遍，而且整批产物收在一个文件夹里。想让子目录各自带产物出去就换
「同级顶层目录」。

**输出文件名称**只写**文件名**：支持 `{name}` `{template}` `{dir}` `{index}`，扩展名由  
「输出格式」决定并自动补在后面，所以这里**没有 `{ext}`**。默认 `{name}` 即保持原名。  
（旧模板里写过的 `{ext}` 会被去掉；`{name}.{ext}` 这样的写法直接写成 `{name}` 就好。）

**「输出格式」就在同一行**，紧跟输出文件名称之后。它决定输出文件的封装格式（也就是  
扩展名），留空沿用源文件的格式。这一项是每个模板自己的选择，不跟随「与全局不同」  
开关——段开着时它排在输出文件名称旁边，段关着时它单独留在原位，始终可编辑。

## 已处理过的文件

**什么时候算「处理过」**：这一次运行里，已经用**同一个模板**把这个文件跑完并验证过。
这时再遇到同一个文件，就**不再重新编码**，只按下面的设置安置源文件。判断依据是程序
自己的记录，不是「输出位置恰好有个文件」——后者是猜，谁放过去的都算数。

**记录只存在内存里，不落盘。** 程序不会在你的视频旁边写任何文件。代价是它不跨进程：
关掉程序再打开，同一个文件会照常处理。这是刻意的——文件夹整理过、产物被手动搬走之后，
一条陈旧的记录只会让你想处理的文件被跳过。想重新处理，关掉程序重开即可。
（「处理记录」那一页的历史是另一回事，它照常落盘。）

`Action` 只有三种，字段和「匹配条件 → 被排除文件的处理」完全一样：

| 处理方式                | 效果                                          |
| ------------------- | ------------------------------------------- |
| 不处理，留在原处              | 本次跳过，不重新编码；源文件留在原处                        |
| 移动到目标目录               | 源文件挪走，让源目录不再重复喂同一个文件                    |
| 复制到目标目录               | 源文件留一份副本，原件不动                             |

**「移动 / 复制」在每次处理完之后就执行**，不需要等第二次：第一次跑完，源文件就按这个
方式被安置走了。第二次遇到的（如果源文件还在）则跳过编码，同样安置一次。

「移动 / 复制」时可选**源文件新名称**给搬走的源文件改名，留空保持原文件名。

这一段**默认不启用**（「基本配置」里它是空的）：它的作用是「同一批文件只处理一次」，
这是少数人需要的默认行为，不该让所有人一上来就撞上。需要时在模板里打开这一段。

目标位置和「匹配条件」用的是同一组「输出方式」。源文件在
`D:\video\mmd\sub\b.mp4`、后缀填 `_done` 时：选「同级目录」进
`D:\video\mmd_done\sub\b.mp4`（保留目录结构开着）或 `D:\video\mmd_done\b.mp4`
（关着）——`mmd` 下面有几层都汇到这一个 `mmd_done`；选「同级顶层目录」进
`D:\video\mmd\sub_done\b.mp4`。

两个细节：

- **记录是「同一个文件 + 同一个模板」**。换一个模板，这个文件会被重新处理一遍；
  同一个文件用另一个模板跑过，不影响这一个。
- **改了模板就会忘掉记录**。保存模板（或「基本配置」）时程序会清掉相应的记录，
  因为那条记录只对改之前的那套参数成立——改完参数重跑，才是你想要的。


## 匹配条件

在处理之前按条件排除文件：体积上下限、长边上下限、时长上下限、扩展名白名单 /  
黑名单。所有条件都可以留 0 或留空，表示不限制。

界面上每个条件框下面都写明了它排除的是**哪一侧**：最小体积填 300，低于 300 MB  
的**不处理**。任务栏那个 chip 同样从「被排除」的角度描述（`排除 <300MB`），
不会读成「只处理 300MB 以上」。

被排除的文件按你选的方式处理：留在原处、移动、或复制。移动 / 复制到哪，用的还是
「输出方式」那一组（自定义目录写 `D:/质检`，或同级目录加个后缀），也可以用
「源文件新名称」改名。

## 错误与警告

- **错误文件**（ffmpeg 报错退出、输出缺失或为空）：保留在原处 / 移动 / 复制。
- **警告文件**（处理成功，但有可恢复的解码告警）：除上述三种外，还可以  
  「只在记录中标记」。

两类文件放哪也用同一组「输出方式」，所以「错误文件按原目录结构汇总到一个质检目录」
这类需求，输出方式选「自定义目录」写 `D:/质检`、再打开「保留目录结构」即可。

移动 / 复制时也可以填**源文件新名称**（与「输出文件名称」同一套变量），留空即保持原文件名。

## 处理性能

| 项         | 说明                                   |
| --------- | ------------------------------------ |
| 同时处理任务数   | 全局值决定工作池大小；单个模板可以调低，但不能调高            |
| 每任务 CPU 核心数 | 给 ffmpeg 传 `-threads`；留 0 交给 ffmpeg 自己决定（界面上会显示本机的逻辑核心数，是运行时识别的，不是写死的） |
| 失败重试次数    | 转码失败后自动重跑                            |
| 日志级别      | 对应 ffmpeg 的 `-loglevel`，默认 `warning` |
| 降低进程优先级   | 以低优先级运行 ffmpeg                       |
| 失败时删除残缺输出 | 中断后清理半成品                             |

显卡编码会争抢资源，建议并发设 1~2；纯 CPU 编码可以按核心数往上加。

## 日志

- **界面保留行数** — 只影响任务面板里显示的最新日志。
- **日志体积上限 / 保留天数** — 写盘日志按这两个限制清理：单个文件超过体积上限  
  时轮转，整个目录里超过保留天数的文件会被删除。启动时和每个任务结束后都会  
  扫一遍，所以长期使用也不会无限占磁盘。

## 处理记录

每次处理都会留下一条记录：输入输出路径、用到的模板、完整命令、状态、处理前后的  
容器 / 分辨率 / 编码 / 体积 / 时长，以及压缩比。

- **筛选** — 关键词（文件名 / 路径 / 模板 / 错误）、状态、**日期区间**（两端都含  
  当天，按记录上的「完成时间」算），再加上「最新在前 / 最早在前」。右边的 × 一次  
  清掉这些条件。
- **每页条数** — 50（默认）/ 100 / 200 / 300，翻页在页面底部的分页条上。
- **多选与移除** — 和任务列表同一套用法：勾选复选框选中，「全选」只指当前这一页；  
  选中后出现批量条，可以一次移除这些记录。移除只删记录，**输出文件不受影响**。
- **导出 CSV** — 导出的是**当前筛选出的全部记录**（不只是这一页），带 UTF-8 BOM，  
  Excel 直接打开不乱码。
- **定位** — 每行两颗：源文件和输出文件。点开详情还能看到这条记录里源文件被搬到了  
  哪里（如果搬过），以及当时执行的那条完整命令。

## 命令预览

- 任务面板的**「命令预览」**：按**选中任务当前绑定的模板**生成，命令随源文件分辨率实时计算，也就是点「开始」真正会执行的那一条；面板右上角有「复制」可以直接拿走。  
  工具栏切换模板会**立刻应用到队列里的所有文件**（第一次添加文件时也不会落到「全局模板」上——那个模板只放默认值，处理不了一个文件）。
- 已经完成的任务会被重新排回「排队中」，这样点「开始」就是按新参数重跑，不会留下一份谁也说不清是怎么来的结果。  
  已经在处理的那条除外——它按开始时用的模板跑完，不会被中途换掉。

源文件读不到（被移动或删除）时会明确标注「按 3840×2160 示例计算」，  
不会悄悄给一份看起来正常、其实与真实文件无关的命令。

## 其他

- **托盘后台** — 关闭窗口时最小化到托盘（可关）。托盘图标**左键单击或双击  
  直接打开主界面**，右键菜单只有「显示主界面」和「退出」两项（暂停/继续  
  放在任务页上，托盘里不再重复）。鼠标悬停在图标上会显示当前队列进度，  
  队列为空时回到普通标题。
- **只开一个** — 程序同时只允许运行一份。再次启动时会把窗口叫出来而不是  
  再开一个（第二个进程在建窗口之前就退出了，不会闪一下、也不会多一个托盘图标）。
- **无感后台启动** — 打开「启动后直接最小化到托盘」后，窗口**从头到尾不出现**，  
  直接进托盘（需要开启系统托盘；没开托盘时这项会被忽略，否则程序就找不回来了）。
- **无边框窗口** — 顶部那条由程序自己绘制：状态信息在左，拖动、双击最大化、  
  最小化与关闭在右上角，占用宽度最小。  
  界面里拖动文字或图片不会误触发「松开即可添加到队列」，只有真的从外面拖文件进来  
  才会。
- **多选批量处理** — 和文件管理器一个用法：**单击一行只是把焦点切过去**（下方的日志、  
  详情、命令跟着换），**勾选复选框**才是选中；**Ctrl+点击**多选、**Shift+点击**连选一段。  
  勾选后出现批量条，可全选、取消选择、一次删除输出或一次移除。  
- **任务和记录都分页** — 每页 50 条，可改成 100 / 200 / 300，翻页在列表底部的  
  分页条上；条数选得再大，界面一次也只画这一页，队列长的时候不会卡。  
  分页条上的「全选」和批量操作都只作用于**当前这一页**。
  处理完成的行会直接显示**处理前后对比**：源值划掉，下面是新值，右侧带百分比。
- **按状态筛选** — 工具栏第一行那个下拉可以把列表收窄到某一类状态（排队中 / 处理中 /  
  已完成 / 失败 / 已取消 / 已跳过·已排除），任务计数会变成「3 / 9 个任务」。  
  这只是视图：被筛掉的任务照样在队列里、照样处理，工具栏的按钮也仍然作用于整个队列。  
  一个都筛不出来时会说明「队列里有 N 个任务，但没有一个属于这一类」。
- **「移除」和「删除」是两件事** — 「移除」（✕）只把这一行从队列里拿掉，**不动任何文件**；  
  「删除」（🗑）只删掉这一行已经生成的**输出文件**，**行会留在列表里**并标上「输出已删除」。  
  删掉输出的行不会假装一切正常：定位输出那一颗会变灰并写明文件已删除，删除也变灰。  
  正在处理的文件删不掉（编码器还开着它，会提示先暂停或移除），**源文件永远不会被删**。  
  批量条上的「删除输出」一次删掉所选任务已经生成的文件。
- **两个定位入口** — 每一行都有两颗：左边那颗定位**源文件**，右边那颗定位**编码后的输出文件**。  
  源文件被「已处理过的文件」或筛选规则搬走之后照样定位得到：程序记着它的落点，会直接开到  
  新位置并告诉你一声。文件真的不在了会明说找不到，而不是默默打开一个空目录。  
  双击一行 = 定位这一行的文件（已经产出的去输出，其余的去源文件）。
- **输出日志自动跟随** — 日志面板跟着最新一行滚动；想往回读的时候它**不会把你拽回底部**，  
  滚回底部就继续跟随。切到「处理详情」「命令预览」再切回来，这期间产生的日志不会丢。
- **两栏一体的界面** — 左侧是 logo + 四个主项目，右侧是当前页内容，中间没有多余的框。  
  顶上也**没有任何标题**：logo 与状态、窗口按钮在同一行，页面直接接在下面，  
  当前在哪一页由左栏高亮的那一项说明。选中项统一用**填充色块**标记，  
  不用左侧色条。  
  右键模板行有「复制模板 / 删除模板」。通知从右上角弹出，点一下即可关掉。
- **防睡眠** — 处理期间阻止系统休眠与屏幕关闭，队列空闲后自动恢复。
- **数据目录** — 程序同目录的 `data/` 文件夹，`settings.json`、`templates.json`、  
  `history.json`、`logs/` 都在里面。拷贝程序时一并带走即可。  
  具体位置在「设置 → 数据日志」里可以看到并一键打开。

## 常见问题

**找不到 ffmpeg**  
到「设置 → FFmpeg 程序」手动指定路径，或点「自动检测」重新扫一遍 `PATH`。

**任务一直「排队中」**  
检查上方是否处于暂停状态，或之前点过「停止」—— 停止后需要重新点「开始」。

**暂停之后进度条不动了，是卡了吗**  
不是。暂停会把 ffmpeg 进程整个冻住，所以进度条本来就不会动，任务上会标着  
「已暂停」。点「继续」它会从停下的那一秒接着转。  

**暂停时关掉了程序，下次会怎样**  
被冻住的进程会在退出前被清理掉，不会留下一个占着 CPU 和输出文件的孤儿 ffmpeg。  
那个转了一半的文件也不会被当成成品：程序不会在它旁边留任何标记，下次遇到同一个  
源文件时照常重新转一遍。

**提示「本次运行已用该模板处理过，已跳过」**  
这是「已处理过的文件」在起作用：这一次运行里，程序已经用这个模板把这个源文件跑完过，
所以不再编码，只按那一段的设置安置源文件。**这一段默认不启用**（「基本配置」里它是
空的），看到这条提示说明你已经打开过它。

重复加进来的同一个文件会被队列自动去重，所以这条提示通常出现在**你先移除那一行、
再重新加进来**的时候——比如重新扫一遍整个目录，只想处理新增的那些文件。

**想让它重新处理一遍怎么办**  
三种办法：关掉再打开程序（记录只在内存里）；把「已处理过的文件」这一段关掉；或者
改一下模板里的处理参数并保存（保存模板会清掉这个模板的记录，因为旧记录只对改之前
的参数成立）。在任务列表里用「删除」删掉产物也会清掉对应的记录。

**提示 `Too many packets buffered for output stream`**  
源文件码率波动大。在模板的「容器与流」里把「混流队列上限」填上（例如 2048），  
其余情况留空即可。

**「定位源文件」说文件不在这里了**  
程序记下的落点也对不上——比如处理完之后又在程序外把文件搬过一次。处理记录里能看到
那条记录记的最终位置，照着找一下在哪。

**命令里为什么有 `-sn`**  
它表示「排除字幕」。来自模板「容器与流」里**未勾选**「保留全部流」——这时只保留  
一路视频 + 一路音频，字幕不带走。勾选「保留全部流」后它会消失，改成 `-map 0` 并  
按容器写入字幕编码（MP4 用 mov_text、MKV 用 copy）。
