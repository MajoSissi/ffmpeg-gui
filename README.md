# FFmpeg GUI

一个基于 ffmpeg / ffprobe 的 Windows 桌面批量处理工具。把一整个文件夹丢进去，  
选一个模板，剩下的交给它：转码、缩放、改容器、抽音轨、转 GIF，以及你临时加的  
任意 ffmpeg 参数。

## 它能做什么

- **批量处理** — 拖入文件或整个目录，递归扫描子目录，一次跑完整批。
- **参数模板** — 把一套 ffmpeg 参数存成模板，随时切换；可复制、可导入导出。
- **分辨率批量转换** — 4K 长边转 2K 这类需求，横屏竖屏自动识别。锁定长边或短边时  
  另一边交给 ffmpeg 按比例计算（命令里是 `-1` / `-2`），程序不做任何取整猜测。
- **命令行预览** — 每个模板、每个任务都能看到将要执行的完整命令，逐行展开。
- **实时监控** — 速度、码率、进度、ffmpeg 原始日志，任务卡里一目了然。
- **后台运行** — 最小化到系统托盘，处理期间可以锁屏继续干活。
- **处理记录** — 记录处理前后的格式、分辨率、体积与压缩比，可导出 CSV。

## 快速开始

### 1. 准备 ffmpeg

程序需要 `ffmpeg` 和 `ffprobe` 两个可执行文件。

- **已经装过**：直接启动即可，程序会从系统 `PATH` 里自动查找。
- **没有装**：从 [ffmpeg.org/download](https://ffmpeg.org/download.html) 下载  
  Windows 版本，解压后打开  
  「设置 → FFmpeg 程序」，把 `ffmpeg.exe` 和 `ffprobe.exe` 的路径填进去。

程序不会附带 ffmpeg，也没有隐藏的下载逻辑 —— 用哪个版本完全由你决定。

> 想要 NVENC / QSV / AMF 硬件编码，需要用带这些编码器的 ffmpeg 构建。  
> 模板编辑器里的「可用的视频编码器」会实时检测当前 ffmpeg 到底支持哪些，  
> 不支持的会灰掉，避免选了才发现。

### 2. 添加文件

把文件或文件夹拖进窗口，或者点「添加文件」「添加文件夹」。目录会递归扫描，  
常见的视频与音频格式都会入队。

### 3. 选模板，点开始

在工具栏选择模板，点「开始」。每个任务都会显示进度、速度与耗时，处理完的文件  
落在输出目录里。

**队列不会自己开跑。** 添加文件、拖入文件、切换模板都只是把任务排进去，必须点  
「开始」才会处理；「暂停」会**把正在转码的进程也一起冻住**——进度停在原地，点  
「继续」后从那里接着转，不会重新开始，也不丢已转的部分；「停止」把队列退回未开始  
的状态。「暂停」在还没点过「开始」时是灰的——队列没启动过，暂停它没有意义。  

暂停中的任务会显示「已暂停」，进度条不再走动——这不是卡死，是真的停住了。  
如果你在暂停时直接关掉程序，那个半成品文件会被记下来，下次遇到同一个源文件时  
**重新转一次**，而不是当成「已经处理过」跳过。

## 模板

模板决定「怎么转」。一个模板包含：编码器与码率控制、分辨率、音频、容器与流、  
滤镜、以及你自己加的额外参数。

程序内置了 11 个常用模板（无损转封装、H.264 1080p、H.265 高压缩、  
4K 长边转 2K、竖屏 1080×1920、定码率、抽音频、Web 优化、转 GIF 等），  
可以直接用，也可以复制一份改成自己的。**列表里的模板可以拖动调整顺序**，  
顺序会保存下来。**右键模板行**有「复制模板 / 删除模板」；顶部的三个小图标  
分别是导入、导出和恢复内置模板。

**哪些参数可以不填**：ffmpeg 本身有默认值的参数，留空即可 —— 程序不会把  
`-crf`、`-b:v`、`-preset`、`-max_muxing_queue_size` 之类硬塞进命令。  
留空就是「交给 ffmpeg 决定」。

**编码器留空**则完全不传 `-c:v`，连带的 CRF / 码率 / preset 也会一起跳过 ——  
因为编码器家族不同，质量参数的写法也不同（libx264/x265 用 `-crf`，  
NVENC / QSV / AMF 用 `-cq`），猜错比不写更糟。只有在你确实填过又被跳过时，  
预览才会给出提示。

**「不填」在界面上只有一种说法**：下拉框叫「默认（由 ffmpeg 决定）」，输入框的  
占位文字是「留空 = 默认」，数值填 0 表示「保持原样」或「不限」。

**输入框随选项联动**：选了「锁定长边」，短边、宽高、百分比这些与当前方式无关的  
框会灰掉；视频选「直接复制」时编码器整组不可用；输出方式选「同级顶层目录 + 后缀」时 
只有「目录后缀」可填，选指定目录类才出现目录框。灰掉的不是被丢弃，只是这一项  
本来就不会进命令。

**新建模板的音频默认是「直接复制」**：多数任务只想重编码视频，音频原样带走既省  
时间也不会更差。

## 全局默认值与「跟随」

模板列表上方有一张**全局默认值**卡片。它不是预设，不参与处理，只提供默认值。

- 新建模板时以它为起点。
- 模板里每一段都有一个「与全局不同」开关：关掉就跟随全局，打开才单独编辑。  
  跟随时那一段只显示一行摘要，告诉你正在继承什么，而不是摆一屏用不上的输入框。
- 五段都受这个开关管：**处理性能 / 输出与命名 / 已处理过的源文件 / 匹配条件 / 错误与警告**。

「与全局不同」是**唯一**表达「跟随」的方式。段内下拉框里没有「跟随全局设置」这一项  
——一个状态给两个控件，界面上就可能出现「看着在跟随、命令里却是别的值」。

所以调整默认行为只需要改一处；要给某个模板破例，单独打开那一段即可。

## 输出与命名

「输出方式」有四种，主输出、被筛掉的文件、出问题的文件都共用这一套：

| 方式                  | 效果                                                  |
| ----------------- | ------------------------------------------------- |
| 与源文件同目录            | 直接写在原处                                              |
| 同级顶层目录 + 后缀（源目录结构） | `/video/mmd` → `/video/mmd_out`，**子目录结构原样保留**             |
| 指定目录                | 所有文件平铺到一个目录                                         |
| 指定目录（源目录结构）        | 指定一个根目录，按原来的层级放进去                                 |

**「同级顶层目录 + 后缀」只改最上层那个目录名，文件名不动**：

```
加入的目录          D:\video\mmd
  其中             D:\video\mmd\a.mp4          →  D:\video\mmd_out\a.mp4
  子目录里的        D:\video\mmd\sub\b.mp4      →  D:\video\mmd_out\sub\b.mp4
```

**为什么推荐它**：结果落在源目录的**同级**位置，而不是源目录里面。这意味着再次  
扫描同一个目录时，不会把上次生成的产物再吃一遍。

命名模板只写**文件名**：支持 `{name}` `{template}` `{dir}` `{index}`，扩展名由  
「输出格式」决定并自动补在后面，所以模板里**没有 `{ext}`**。默认 `{name}` 即保持原名。  
（旧模板里写过的 `{ext}` 会被忽略，不会变成 `clip..mp4`。）

**「输出格式」就在同一行**，紧跟命名模板之后。它决定输出文件的封装格式（也就是  
扩展名），留空沿用源文件的格式。这一项是每个模板自己的选择，不跟随「与全局不同」  
开关——段开着时它排在命名模板旁边，段关着时它单独留在原位，始终可编辑。

## 已处理过的源文件

同一个模板跑第二遍时，输出位置已经有文件了——说明这个**源文件**之前处理过。这一段
决定那个源文件怎么办，字段和「匹配条件 → 被排除文件的处理」完全一样：

| 处理方式                | 效果                                          |
| ------------------- | ------------------------------------------- |
| 不处理，留在原处              | 本次跳过，不重新编码；源文件留在原处                        |
| 移动到目标目录               | 源文件挪走，让源目录不再重复喂同一个文件                    |
| 复制到目标目录               | 源文件留一份副本，原件不动                             |

三种方式下**本次都不会再编码**——已经处理过的文件重跑一遍只是白费时间。「移动 / 复制」
时可选**命名模板**给搬走的源文件改名，留空保持原文件名。

这一段**默认不启用**（「基本配置」里它是空的）：它的作用是「同一批文件只处理一次」，
这是少数人需要的默认行为，不该让所有人一上来就撞上。需要时在模板里打开这一段。

目标位置和「匹配条件」用的是同一套规则：以**源目录**为基准。源文件在
`D:\video\mmd\sub\b.mp4` 时选「同级顶层目录 + 后缀 `_done`」，它进
`D:\video\mmd_done\sub\b.mp4`——不是每一层都长出一个 `_done` 文件夹。

一个细节：**零字节的残留不算「已处理过」**。那是上次中断留下的半成品，否则用户想重跑
的那一次正好被跳过。

## 匹配条件

在处理之前按条件排除文件：体积上下限、长边上下限、时长上下限、扩展名白名单 /  
黑名单。所有条件都可以留 0 或留空，表示不限制。

界面上每个条件框下面都写明了它排除的是**哪一侧**：最小体积填 300，低于 300 MB  
的**不处理**。任务栏那个 chip 同样从「被排除」的角度描述（`排除 <300MB`），
不会读成「只处理 300MB 以上」。

被排除的文件按你选的方式处理：留在原处、移动到目标目录、或复制过去。目标目录  
同样有上面那四种输出方式，也可以用重命名模板改名。

## 错误与警告

- **错误文件**（ffmpeg 报错退出、输出缺失或为空）：保留在原处 / 移动 / 复制。
- **警告文件**（处理成功，但有可恢复的解码告警）：除上述三种外，还可以  
  「只在记录中标记」。

两类文件的目标目录也支持全部四种输出方式，所以「错误文件按原目录结构汇总到  
一个质检目录」这类需求不需要额外技巧。

移动 / 复制时也可以填**命名模板**（与「输出与命名」同一套变量），留空即保持原文件名。

## 处理性能

| 项         | 说明                                   |
| --------- | ------------------------------------ |
| 同时处理任务数   | 全局值决定工作池大小；单个模板可以调低，但不能调高            |
| 每任务 CPU 核心数 | 给 ffmpeg 传 `-threads`；留 0 交给 ffmpeg 自己决定（界面上会显示本机的逻辑核心数，是运行时识别的，不是写死的） |
| 失败重试次数    | 转码失败后自动重跑                            |
| 日志级别      | 对应 ffmpeg 的 `-loglevel`，默认 `warning` |
| 降低进程优先级   | 以低优先级运行 ffmpeg                       |
| 失败时删除残缺输出 | 中断后清理半成品                             |

显卡编码会争抢资源，建议并发设 1~2；纯 CPU 编码可以按核心数往上加。

## 日志

- **界面保留行数** — 只影响任务面板里显示的最新日志。
- **日志体积上限 / 保留天数** — 写盘日志按这两个限制清理：单个文件超过体积上限  
  时轮转，整个目录里超过保留天数的文件会被删除。启动时和每个任务结束后都会  
  扫一遍，所以长期使用也不会无限占磁盘。

## 处理记录

每次处理都会留下一条记录：输入输出路径、用到的模板、完整命令、状态、处理前后的  
容器 / 分辨率 / 编码 / 体积 / 时长，以及压缩比。可以按关键词和状态筛选，  
也可以导出 CSV（带 UTF-8 BOM，Excel 直接打开不乱码）。

## 命令预览

- 任务面板的**「命令预览」**：按**选中任务当前绑定的模板**生成，命令随源文件分辨率实时计算，也就是点「开始」真正会执行的那一条；面板右上角有「复制」可以直接拿走。  
  工具栏切换模板会**立刻应用到队列里的所有文件**（第一次添加文件时也不会落到「全局模板」上——那个模板只放默认值，处理不了一个文件）。
- 已经完成的任务会被重新排回「排队中」，这样点「开始」就是按新参数重跑，不会留下一份谁也说不清是怎么来的结果。  
  已经在处理的那条除外——它按开始时用的模板跑完，不会被中途换掉。

源文件读不到（被移动或删除）时会明确标注「按 3840×2160 示例计算」，  
不会悄悄给一份看起来正常、其实与真实文件无关的命令。

## 其他

- **托盘后台** — 关闭窗口时最小化到托盘（可关）。托盘图标**左键单击或双击  
  直接打开主界面**，右键菜单只有「显示主界面」和「退出」两项（暂停/继续  
  放在任务页上，托盘里不再重复）。
- **只开一个** — 程序同时只允许运行一份。再次启动时会把窗口叫出来而不是  
  再开一个（第二个进程在建窗口之前就退出了，不会闪一下、也不会多一个托盘图标）。
- **无感后台启动** — 打开「启动后直接最小化到托盘」后，窗口**从头到尾不出现**，  
  直接进托盘（需要开启系统托盘；没开托盘时这项会被忽略，否则程序就找不回来了）。
- **无边框窗口** — 顶部那条由程序自己绘制：状态信息在左，拖动、双击最大化、  
  最小化与关闭在右上角，占用宽度最小。  
  界面里拖动文字或图片不会误触发「松开即可添加到队列」，只有真的从外面拖文件进来  
  才会。
- **多选批量处理** — 和文件管理器一个用法：点击选中一行，**Ctrl+点击**多选、  
  **Shift+点击**连选一段，复选框与点击共用同一份选中集；勾选后出现批量条，  
  可全选、取消选择或一次移除。  
  处理完成的行会直接显示**处理前后对比**：源值划掉，下面是新值，右侧带百分比。
- **两栏一体的界面** — 左侧是 logo + 四个主项目，右侧是当前页内容，中间没有多余的框。  
  顶上也**没有任何标题**：logo 与状态、窗口按钮在同一行，页面直接接在下面，  
  当前在哪一页由左栏高亮的那一项说明。选中项统一用**填充色块**标记，  
  不用左侧色条。  
  右键模板行有「复制模板 / 删除模板」。通知从右上角弹出，点一下即可关掉。
- **防睡眠** — 处理期间阻止系统休眠与屏幕关闭，队列空闲后自动恢复。
- **数据目录** — 程序同目录的 `data/` 文件夹，`settings.json`、`templates.json`、  
  `history.json`、`logs/` 都在里面。拷贝程序时一并带走即可。  
  具体位置在「设置 → 数据日志」里可以看到并一键打开。

## 常见问题

**找不到 ffmpeg**  
到「设置 → FFmpeg 程序」手动指定路径，或点「自动检测」重新扫一遍 `PATH`。

**任务一直「排队中」**  
检查上方是否处于暂停状态，或之前点过「停止」—— 停止后需要重新点「开始」。

**暂停之后进度条不动了，是卡了吗**  
不是。暂停会把 ffmpeg 进程整个冻住，所以进度条本来就不会动，任务上会标着  
「已暂停」。点「继续」它会从停下的那一秒接着转。  

**暂停时关掉了程序，下次会怎样**  
被冻住的进程会在退出前被清理掉，不会留下一个占着 CPU 和输出文件的孤儿 ffmpeg。  
但那个没转完的文件会被记下来，下次再遇到同一个源文件时**重新转一遍**，而不是  
当成「已处理过」跳过——省得你看着一个残缺的成品发呆。

**提示「该文件此前已用此模板处理过，已跳过」**  
这是「已处理过的源文件」在起作用：输出位置已经有文件，说明这个源文件上一轮处理过，
本次不再编码。**这一段默认不启用**（全局模板里它是空的），所以看到这条提示说明你已经
打开过它——把该段的「与全局不同」关掉即可恢复「看到已有文件也照跑」。

**提示 `Too many packets buffered for output stream`**  
源文件码率波动大。在模板的「容器与流」里把「混流队列上限」填上（例如 2048），  
其余情况留空即可。

**「定位源文件」打开的是别的位置**  
文件在处理过程中可能已被移动（筛选转移或错误处理）。用任务卡上的路径重新定位，  
或查看处理记录里的最终位置。

**命令里为什么有 `-sn`**  
它表示「排除字幕」。来自模板「容器与流」里**未勾选**「保留全部流」——这时只保留  
一路视频 + 一路音频，字幕不带走。勾选「保留全部流」后它会消失，改成 `-map 0` 并  
按容器写入字幕编码（MP4 用 mov_text、MKV 用 copy）。
